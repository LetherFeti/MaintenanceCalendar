# お手入れカレンダー

所持品の使用・お手入れを記録する小さなWindows用カレンダーです。

## 起動

Windows 11 / .NET 10 Desktop Runtimeが必要です。開発には.NET 10 SDKを使用します。

```powershell
dotnet build MaintenanceCalendar.slnx -c Release
.\MaintenanceCalendar\bin\Release\net10.0-windows\MaintenanceCalendar.exe
```

NuGet.Configはこのプロジェクトだけ公式NuGetを参照します。NLogとEntity Framework Core 10（SQLite）を使用します。実行フォルダへデータを書き込むため、書込権限のある場所に配置してください。配布する際は製品側のビルド出力フォルダ全体をコピーします。

## 構成と見た目

MVCに近い役割名でフォルダを整理しています。WPFの画面とコードビハインドは同じ場所に置き、名前空間・型名・既存の画面イベントは維持しています。

| フォルダ | 役割 |
| --- | --- |
| `MaintenanceCalendar/Models` | 所持品・履歴・祝日・設定などのモデル。1型1ファイル |
| `MaintenanceCalendar/Models/Persistence` | EF CoreのDbContext、DB検索・更新、SQLite保守処理 |
| `MaintenanceCalendar/Views` | Calendar、Items、Care、History、Dashboard、Settings、Notificationsの画面 |
| `MaintenanceCalendar/Views/Shared` | 共通画面・コントロール生成・スタイル・アニメーション |
| `MaintenanceCalendar/Controllers` | 各画面で共有するサービスの組み立てと写真操作の窓口 |
| `MaintenanceCalendar/Services` | バックアップ、祝日取得、スタートアップ、Windows通知 |
| `Test` | 独立した検証コード・フィクスチャ・検証資料 |

通常のメソッドと明示的なコンストラクターに、日本語のXMLドキュメントコメント（`summary`）を付けています。モデルとプライマリコンストラクターを持つ型には型の説明を、ローカル関数には処理内容のコメントを記載しています。

共通WPFスタイルで角丸のボタン・入力欄・選択欄、一覧の配色、カレンダーのカード表示を適用しています。ホバー・押下・ドロップダウン・画面表示・月切替にアニメーションを追加しました。画面と月表示のフェードはWindowsのアニメーション設定を尊重します。設定のテーマ色・背景色・日付マークは従来どおり反映されます。

データの検索・更新・集計はEF Core/LINQで実装し、既存DBのテーブル名、列順、複合キー、索引、日付の `yyyy-MM-dd` 形式を保持しています。既存テーブルを作り直しません。SQLite固有の `PRAGMA`（版番号・整合性・外部キー検査）とバックアップAPIのみ `Models/Persistence/SqliteMaintenance.cs` に分離しています。

## 操作

1. サイドバーの所持品アイコンかアプリ内の右クリックから所持品マスタを開き、メーカー・モデルを登録します。写真は選択またはドロップで取り込めます。行を選んで編集・コピー、チェックしてまとめて論理削除・復旧できます。
2. 右クリックの「お手入れマスタ」にブラッシング等の語句を登録します。
3. 日付を押し、所持品を選んで「使用」「お手入れ」を記録します。使用は再クリックで取消。手入れメモは複数のマスタ語句を追加して自由に追記・編集できます。
4. メインのコンボは空欄なら全有効品、選択するとその品の記録を表示します。コンボの品名にマウスを置くと写真を表示します。
5. 「通知」は手入れ期限の一覧、「履歴」は最終使用・手入れと過去の記録、「▥」は統計です。初回未手入れの期限は購入日、未入力なら登録日が基準です。
6. 「⚙」は色・今日の図形・サイドバーの表示位置（上下左右）、祝日取得、バックアップ/復元、スタートアップの設定です。祝日は初期状態では未取得です。

サイドバーの鍵アイコンまたは右クリックの「誤クリック予防」でON/OFFを切り替えます。有効時もサイドバーと右クリックの解除・終了は使えます。マウスによる前面化を抑えますが、OSのタスク切替までは禁止しません。Windowsのシャットダウンをキャンセルする処理はありません。

サイドバーは常時表示され、先頭のハンバーガーボタンで「アイコンのみ」と「アイコン＋文字」を切り替えます。表示位置と文字の表示状態は次回起動時も引き継ぎます。上下配置で横幅が足りない場合は横スクロールできます。すべての画面の上部には移動・最小化・最大化・終了の操作領域を常時表示し、Windows 11の角丸を適用します。終了時の通常表示の位置と大きさを記憶し、モニター変更時は画面内に補正して復元します。

## データと保守

* `Data/calendar.db`: 所持品、履歴、手入れマスタ、祝日。
* `Data/Photos`: 長辺最大720pxの写真。コピー元も利用できるよう、差替え後の写真は自動削除しません。
* `Data/settings.json`: 色・図形・祝日取得時刻・サイドバーの配置と文字表示・ウィンドウ位置と大きさ。
* `Logs`: NLogの保守ログ。メモ本文や写真内容は記録しません。30日、最大60ファイル、約5MB単位で保持します。

設定画面で `Data/` を含むZIPを作成できます。停止中にアプリフォルダへそのまま展開するか、設定のインポートから復元します。インポート直前のデータは `Data-before-import-日時-識別子` に退避します。必要に応じて退避フォルダを別の場所へ保管してください。

スタートアップはユーザーのスタートアップフォルダに専用ショートカットを作ります。アプリを移動したら再登録してください。Windows通知は集中モードや通知設定に左右されるため、アプリ内の通知一覧でも確認できます。通知に写真は含めません。

## 検証の実行

```powershell
dotnet build Test/MaintenanceCalendar.Test.csproj -c Release
dotnet Test/bin/Release/net10.0-windows/MaintenanceCalendar.Test.dll --self-test
dotnet Test/bin/Release/net10.0-windows/MaintenanceCalendar.Test.dll --ui-test
dotnet Test/bin/Release/net10.0-windows/MaintenanceCalendar.Test.dll --performance-test
```

検証コード・旧DBフィクスチャ・検証記録はすべて `Test/` に集約し、製品のソリューションや配布物から独立しています。`--self-test` は一時DBで機能・旧版DB互換性を検証、`--ui-test` は実WPFコントロールで11画面の生成・描画・一部操作・設定連携、`--online-test` は内閣府CSVの実接続、`--performance-test` は100万件の一時DBで性能を検証します。本番Dataフォルダとは分離します。結果と画面描画はテスト出力先の `Logs` と `Previews` に保存します。

検証が不要になったら `Test/` フォルダを削除できます。製品ソリューションはテストを参照していないため、そのままReleaseビルドできます。製品EXEに検証モードは含めていません。

## タスクトレイと入力候補

最小化するとタスクバーから表示を外してタスクトレイへ格納します。子画面の最小化でもアプリ全体を格納し、編集中の内容を保持します。トレイアイコンのダブルクリックまたは右クリックの「開く」で復元し、「終了」でアプリを終了できます。子画面を編集中の「終了」はその画面を復元します。通知バルーンのクリックでは期限一覧を開きます。

所持品のメーカー・モデル候補は、実行フォルダの `Catalog/manufacturer-model.csv` を読み込みます。UTF-8の2列CSVで、先頭行は `メーカー,モデル`、以降は1行につき1組を記載してください。カンマや引用符を含む値は通常のCSVの引用符規則に対応します。少数の初期候補を同梱し、CSVを追記・変更すると次に登録・編集画面を開いた際に反映します。メーカーは入力文字で候補を絞り、モデルは選択したメーカーに対応する候補を表示します。メーカー未入力でモデルを選ぶとメーカーも補完します。↑↓で候補を移動し、TabまたはEnterで確定、Escで閉じます。マウスでも選択でき、CSVにない値も手入力できます。CSVが欠落・不正でも手入力は利用できます。
